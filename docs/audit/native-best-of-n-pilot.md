# Native script Best-of-N pilot

The optional implementation is isolated source, not a live deployment or a measured scientific gain.
Default `best_of_n_pilot: null` keeps historical static/foresight/listwise selection unchanged.
When explicitly configured, one generated native program contains the statically valid code-only
candidates. The Developer renders this immutable program and executes nothing during generation.
Native proposal commitment, `node_created`, admission, resource reservation and `node_eval_started`
therefore all precede its first pilot, including speculative builds. Discarded unexecuted builds
retain the ordinary refund rule; a running method already crossed the normal evaluation boundary.

A declaration contains exactly `env`, `timeout_seconds` and `fidelity_review`. For example an
operator may declare `{"env":{"TASK_FIDELITY":"smoke"},"timeout_seconds":5,
"fidelity_review":"Exploratory method fixture; rank agreement has not been measured"}`.
This is an explicit experimental method with additional runtime, not an automatic new run/arm.
It requires `backend=llm`, the default in-process developer and `best_of_n=2..8`.
The object is edited in config/API rather than a generic environment-variable text box.
An old snapshot without the field receives null, so a new server's ambient setting cannot add
pilot executions to a historical run. Native resources, budget, protocol, stop and source guards
remain in force; this field is not a Root approval or an ML launch gate.

Supported tasks return their answer as a single `solution.py` script and optional declared text
assets. Repository commands, side-file patches, host grading, parameter-only search and external
harness mode are refused. Unsupported task/runtime declarations are checked before model-client
construction. POSIX `waitid` with `WNOWAIT` is required. No unsupported path silently drops to
static ranking or an unmetered helper execution. A partial/rollback-requesting build is refused.
Each candidate or the common idea must declare its GPU count (0 for CPU); a missing count
refuses to guess an envelope. The footprint takes the maximum sequential candidate count and
known memory demand, retaining unknown memory as unknown. No statically chosen candidate's audit report may claim to describe the later runtime winner.

Inside the one normally admitted node, each eligible candidate runs sequentially under the native
device environment and operator-declared pilot env. Every candidate has a fresh workspace; only
explicit text assets are copied, after exact SHA-256 validation. Links and changed inputs refuse.
The method records each candidate code digest, native-program subprocess exit/timeout, bounded
output digests/references, elapsed seconds and usable pilot metric. Nonzero exit, timeout, boolean,
nonfinite or missing metric cannot win, even if the program printed a metric before it failed.
Ties keep the first eligible candidate. With no usable pilot, the method fails without a full
run or a silent static/LLM fallback. These are program-authored diagnostics tied to the recorded
native source, not a new independent grading authority.

The winner runs again in another fresh workspace with the ORIGINAL environment, using the full
node's ordinary timeout. Its stdout metric is the native result. Pilot diagnostics use a separate
`best_of_n_pilot` JSON key and cannot become a primary metric. The final diagnostic also identifies
the chosen source digest and full output reference. All pilots, the full run and their overhead
are inside the original node wall-time and budget. Native timeout/stop kills the current child
session; normal completion cleans its group before moving on. The source program is self-contained,
so it does not import a possibly absent LoopLab installation in an evaluation image.

CPU acceptance drives the actual sandbox and ordinary Engine, including admission before execution,
one invocation and terminal, exact total charged time, min/max measured selection, failure/timeout,
full-result separation, fresh assets, unchanged original inputs/env, stop, normal-exit forked-worker
cleanup, native proposal/discard contracts and historical selection. This is not target-platform
Docker/Windows/GPU evidence, hostile-code isolation or a remote-execution claim. Existing native
sandbox limitations remain. The method's selected full metric can be worse than the other full
candidate: cheap/full rank preservation has NOT been measured here. The canonical
`smoke-full-rank-fidelity-unmeasured` and matched harness/production utility bounds remain OPEN.
The authored fidelity review records this limitation; it is not a fidelity certificate.
