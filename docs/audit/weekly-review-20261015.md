## Подтверждённые находки

### 1. P1 — удалённый файл возвращается из зеркала

Slug: `weekly-mirror-deletion`.
Место: `looplab/events/run_mirror.py::mirror_run`.

После первого прохода удалить из исходного рана `gpu_gate.json` с `hold=true`,
не меняя остальные файлы, и выполнить второй проход. Он копирует ноль файлов;
локальное состояние теряет строку, но манифест назначения её сохраняет.
`restore_run` успешно восстанавливает удалённый gate вместе со старым hold.
Та же проблема относится к другим удалённым sidecar-файлам.

Удаление строк должно помечать манифест изменённым. Приёмка: проход с одними
удалениями обновляет манифест; восстановление не возвращает удалённые файлы,
в том числе после перезапуска процесса зеркалирования.

_Закрыто 2026-10-16: `mirror_run` ставит `manifest_stale` при каждом удалении строки, поэтому
проход только с удалениями переписывает манифест (и после зависшей записи, и после потери
state-файла); регрессии — `tests/test_run_mirror.py::test_a_deletion_only_pass_rewrites_the_manifest_and_restore_does_not_resurrect`
и `test_a_deletion_survives_a_mirror_restart_between_the_pop_and_the_manifest`._

### 2. P1 — конфликт предрегистрации считается успешным повтором

Slug: `weekly-registration-conflict`.
Место: `looplab/harness/composite.py::submit_experiment`.

Зарегистрировать E1, затем вызвать составной submit с новым ключом, тем же E1,
другой гипотезой и `correction=none`. Реальный маршрут регистрации возвращает
409 `experiment_exists`, но составная операция отмечает шаг `ok=true`,
записывает `inject_node` и возвращает общий успех. В журнале остаётся исходная гипотеза.

Точный повтор уже получает исходную квитанцию через action_id. Для повторного
использования ID другим запросом нужно сверять сохранённую декларацию.
Приёмка: отличающаяся декларация останавливает submit до inject; точный повтор
продолжает работать без повторных записей.

_Закрыто 2026-10-16: 409 `experiment_exists` несёт `same_declaration`; составной submit
продолжает только при совпадении сохранённой декларации, иначе останавливается до inject
(`tests/test_campaign_composite.py`)._

### 3. P1 — обещанное восстановление worktree теряет незавершённую работу

Slug: `weekly-worktree-restore-loss`.
Место: [руководство deployment](../guide/deployment.md), раздел зеркалирования;
реализация — `looplab/events/run_mirror.py`, `SKIP_SUBTREES`.

В настоящем ране создать worktree `draft`, изменить файл и закоммитить его,
не отправляя inject. После mirror → restore → `sync_run` список worktree пуст,
а уникальный commit SHA не разрешается в восстановленном приватном репозитории.
Записанные попытки при этом восстанавливаются. Несохранённые правки в worktree
также исключены из копии.

Утверждение «code/worktrees rebuilt by code-status --sync» неверно для этого
поддерживаемого рабочего процесса. Нужно сохранять агентские refs, метаданные
и незавершённые правки либо явно предусмотреть отдельный backup.
Приёмка: восстановить ещё не отправленное предложение с его историей и файлами.

_Закрыто 2026-10-16: `looplab run-mirror` на каждом проходе (через новый `MirrorConfig.run_extras`)
строит `code_worktree.py::agent_backup` — полный `git bundle` веток `agent/*` плюс коммит
незакоммиченных файлов каждого worktree и его метаданные — в spool зеркала, только читая ран, и
зеркалирует его как `code/agent_backup/`; `sync_run` после восстановления пересоздаёт ветки и
worktree с грязными файлами (`restore_agent_worktrees`). Остаток: грязные файлы сверх
`MAX_BACKUP_DIRTY_BYTES` и bundle сверх `--max-file-mb` не сохраняются (названы в записи).
Регрессия на настоящем git — `tests/test_code_identity.py::test_an_unsubmitted_agent_worktree_survives_mirror_wipe_restore_and_sync`._

### 4. P2 — экспорт теряет executable bit

Slug: `weekly-export-file-mode`.
Место: `looplab/engine/code_export.py::_delta_step`; аналогичная логика в `_base_step`.

Исходное `train.sh` имеет режим 100644. Commit рана меняет содержимое и режим
на 100755. Экспорт через настоящий Git создаёт новый commit с новым содержимым,
но режимом 100644. Изменение только режима пропускается как already present,
поскольку равенство проверяется только по blob SHA.

Сравнивать и переносить нужно пару mode/blob, разрешая конфликт режима отдельно
от слияния текста. Приёмка: экспорт сохраняет chmod как с изменением текста,
так и без него, а конфликтующие изменения режима не скрываются.

_Закрыто 2026-10-16: `code_export.py::_carry` сравнивает и переносит пару (mode, blob) в
`_delta_step` и `_base_step`; режим разрешается отдельно от текста (`_merged_mode`), конфликт режима
останавливает экспорт и называется в `mode_conflicts`; в базовом шаге режим рабочего дерева
учитывается, только если у цели не `core.fileMode=false`. Регрессии с настоящим Git — в
`tests/test_code_identity.py` (chmod с изменением текста и без, конфликт режимов)._

### 5. P2 — повреждённые строки журналов не закрывают запись

Slug: `weekly-journal-shape-health`.
Места: `looplab/harness/campaign.py::read_journal` и
`looplab/harness/per_query.py::read_manifest`.

Поместить строку `{"action_id":"lost"}` в журнал протокола. Чтение показывает
`invalid_record_rows=1` одновременно с `read_complete=true`.
Реальный маршрут после этого принимает новую регистрацию и присваивает version=1.
Чтение manifest per-query демонстрирует ту же ошибку признака полноты.

Отброшенная строка может содержать прежнюю операцию; отсутствие корректной записи
не доказывает отсутствие операции. Проверку формы следует включить в read_complete,
как уже делает `looplab/harness/journals.py::receipt_records`.
Приёмка: обе записи отказывают на структурно повреждённой истории до её восстановления.

_Закрыто 2026-10-16: `read_journal` и `read_manifest` снимают `read_complete`, если проверка
формы отбросила строку; запись отвечает 503 `harness_history_incomplete`._

### 6. P2 — разные наборы запросов получают один test_id

Slug: `weekly-shared-test-delimiters`.
Место: `looplab/harness/per_query.py::test_id_for`.

Две JSON-загрузки через настоящий HTTP-маршрут:

| Загрузка | query ids | clusters |
|---|---|---|
| A | `["a\tb", "z"]` | `["c", "u"]` |
| B | `["a", "z"]` | `["b\tc", "u"]` |

Обе принимаются с HTTP 200 и получают
`qs1-7c0d09716dc493355ddc6b3fd9a9216a`. Это коллизия сериализации, не SHA-256:
табуляция одновременно разделитель и допустимая часть метки.
Сравнение доверяет test_id и может сопоставить разные запросы по позиции.

Нужна однозначная сериализация пар либо отказ для разделителей.
Приёмка: разные пары не сливаются, перестановка одних и тех же пар сохраняет ID;
отдельно проверить переводы строк и совместимость старых загрузок.

_Закрыто 2026-10-16: метка с табуляцией или переводом строки отклоняется (400) при загрузке и
в `test_id_for`; ID однозначных загрузок не изменились (сериализация `qs1-` та же)._

### 7. P2 — отпечаток данных пропускает ссылки на каталоги

Slug: `weekly-data-directory-links`.
Место: `looplab/harness/campaign.py::content_fingerprint`.

В каталоге mount создать `train` как symlink на dataset A, затем перенаправить
его на dataset B. Оба отпечатка совпадают и показывают `files=0`,
`truncated=false`. `os.walk` помещает ссылки на каталоги в dirnames, но код
обрабатывает только filenames, хотя docstring обещает учитывать цель внутренних ссылок.

Учитывать такие ссылки без обхода их содержимого.
Приёмка: изменение цели ссылки меняет digest; ссылочные циклы не обходятся.

_Закрыто 2026-10-16: ссылки на каталоги из `dirnames` хэшируются по цели вместе с файлами,
без обхода их содержимого._
