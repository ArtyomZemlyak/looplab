# Native metric behavior observations

12 November 2026. Isolated source implementation; not published or deployed.

The historical §69.13 gap was real: code/cheating detectors inspected source, not a numerical
regime shift across recorded co-metrics. A separate deterministic `metric_regime_shift` observer
now records `metric_behavior_scan` after a genuine evaluated terminal. The event is folded into
an advisory projection, separate from `reward_hack_suspected`, with no score, feasibility, winner,
launch or automatic lesson-verdict change. It makes no model call and requests no evaluation/repeat.
The existing conservative reservation authority fence remains intact.

## What is checked

Only finite co-metrics from operator-declared readers with explicit directions are eligible.
Auto-captured candidate stdout keys, unknown channels/directions, reconstructed maps, infeasible,
retired, aborted, salvaged or missing-primary outcomes are not comparison evidence. References
must have earlier terminal sequences, the same known integer protocol version, and compatible
measured/declared comparability records. Equal legacy null or inferred-only identities do not
establish comparability. Declared equality still means an operator assertion, not independent
attestation of data/evaluator semantics. A declared stdout reader does not make its value immune
to a dishonest candidate. This observer is not an anti-forgery detector.

The reference window is the latest 32 eligible terminal outcomes, selected by order without
looking at their values. For each positive co-metric with at least three positive references,
the observer compares the current value with their median. Ratios outside [0.5, 2] count as shifts.
At least three checked co-metrics and at least two shifted metrics, comprising at least a quarter
of the checked population, produce `regime_shift`. Both directions of movement count; the observer
never decides which objective is scientifically correct. Nonpositive values and unrepresentable
ratios are excluded; insufficient coverage is `insufficient_evidence`, not a clean certificate.
The stable positive midpoint avoids overflow when an even-sized finite reference set is large.

The receipt binds exact node/attempt/terminal/protocol and primary facts, full observation digests,
original reference IDs/attempts, counts, fixed parameters and the three strongest numerical shifts.
Each displayed shift retains original values, reference median/count and original reference values.
Full metric maps are digested rather than copied into every reference. The output is bounded even
at the native extra-metric limit. The fold reconstructs the observation against native facts and
compares canonical JSON identities, so boolean/integer aliases, forged outcomes and unknown fields
cannot masquerade as a valid receipt. Missing receipts remain unknown, including a crash after
terminal publication and before the observation row.

## Reading and freshness

The Trust panel shows up to ten latest original observations with original numbers and an explicit
advisory label. The owner state/SSE projection computes freshness from full native state; internal
terminal sequence metadata is not invented from the public Node DTO. Reset or changed subject/
reference facts make an original observation historical. No quarantine or execution action is
attached to it. `looplab inspect` and the proposal brief expose bounded current warnings inside an
untrusted-data fence. They ask whether objective, population, target or evaluator changed, without
requesting new execution. They do not automatically rewrite an existing supported lesson or turn
an observation into a causal claim.

Optional report review includes this evidence when present. An observation arriving after a review
makes its advice historical. Exact original paid receipts still validate against their captured
prefix and replay without repayment. Prefixes without this new event keep their original v1 input.

## Acceptance

`tests/test_metric_behavior.py` checks numerical positive/negative controls, exact original values,
known protocol/comparability/channel requirements, bounded terminal-order selection, nonpositive/
underflow/overflow boundaries, forged/boolean receipts, native replay, reset freshness, real owner
HTTP projection, real CLI read-only behavior and the maximum declared metric population. Its full
CPU integration runs four actual subprocess evaluations through a protected evaluator and declared
readers, then checks the native observation, public warning and unchanged winner. The test uses an
explicit empty GPU inventory and CPU footprint. An initial fixture tried to edit the protected
scorer and omitted launch snapshots; the native guards correctly refused/made comparability unknown.
The corrected fixture varies only an editable input and supplies actual task/protocol snapshots.
No production guard was weakened. Existing static perfect-score warnings remain unchanged.

The shared Python/native fixture also drives mounted UI tests for original shifts, historical
references, malformed/unsupported metadata and absent evidence. Localized production UI build,
existing event/partition/payload/permission/report-review/proposal/replay/repair contracts and strict
docs are part of source acceptance. Final targeted acceptance: 532 CPU passed, three
existing optional tests skipped; 28 mounted UI/trust/review/catalogue tests passed, localized Vite
production build and strict MkDocs passed. No live or production acceptance is inferred. Event payload probes use a valid post-terminal prefix and prove
that unknown keys are rejected; they do not turn a refused empty probe into false coverage.

Expanded golden checks exposed stale additive fields from earlier scoped direction lifecycle and
post-evaluator timing work. Before refresh, every prior repair-event row and payload key order
compared byte-exact after removing only the new observation and timing subtree; every prior legacy
RunState leaf stayed equal. The snapshot adds only two empty maps, and timing keys remain pinned
with clock values masked. Original event logs and historical incident records were preserved.

## Measurement still owed

The numerical thresholds and positive-only population are deliberately uncalibrated. Synthetic
controls prove the implemented rule and native plumbing, not sensitivity/specificity, scientific
utility, production adoption, or evaluation faithfulness. They cannot certify the old §69.13 run:
unknown old co-metric provenance/protocol remains unknown. Before changing thresholds, enabling
memory-verdict policy, or treating a warning as a gate, an annotated fixed real corpus must measure
coverage, false alerts and missed shifts, with known intended objective/population/evaluator changes
and frozen selection criteria. No extra fit/seed/score is authorized by this document.

The canonical measurement item lives in §69.13 under `metric-behavior-thresholds-unmeasured`.
Only a genuine accepted result belongs at `docs/audit/metric-behavior-threshold-measurement.md`;
no placeholder result is supplied. Native scalar anomalies remain distinct from the existing
`evaluation-faithfulness-not-attested` acceptance gap and from benchmark cheat-detector hack rates.
