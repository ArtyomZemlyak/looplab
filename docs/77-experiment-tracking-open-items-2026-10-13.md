# 77. Учёт экспериментов: незакрытые возможности, запрошенные оператором

Дата: 2026-10-13. База: `22e2e345c`. Запрос — получить в LoopLab удобный учёт кода, параметров, файлов и ресурсов, привычный по MLflow. Ниже собственные требования к LoopLab, не сравнительный аудит актуальной версии MLflow и не обещание готовой совместимости. Связанные документы: [doc 76](76-external-agent-ux-open-items-2026-10-13.md), [doc 46](46-params-proposed-vs-run-2026-08-20.md), [doc 37](37-node-workspace-worktree-measurement-2026-08-13.md).

## 1. Код, на котором выполнен эксперимент — P1

OPEN[experiment-source-snapshot] proof:`absent:SourceSnapshotPanel@ui/src/Inspector.jsx`

**Есть.** Патчи узлов, source/base digests и Git-экспорт DAG. Эти сведения нельзя свести к одному HEAD: кандидат может содержать незакоммиченные изменения.

**Нужно.** Единый снимок исходников для попытки: repository, исходный commit, состояние dirty, digest/артефакт diff и применённые изменения кандидата. В Inspector предложен SourceSnapshotPanel со ссылками на содержимое снимка. Явно различать declared, captured и unknown; не выводить токены из remote URL и конфигурации Git. Локальный commit не требует автоматического push пользовательского репозитория.

**Приёмка.** Два узла с одинаковым HEAD и разным dirty diff показаны как разные снимки. Повторная попытка, смена базы и архивный запуск привязаны к своим исходникам; недоступный Git показывается как unknown, не как clean. Снимок позволяет определить фактически выполненный код и не меняет результаты оценки.

**Данные есть (2026-10-14, doc 79 §3).** Каждая попытка — коммит приватного репозитория прогона
(`code_snapshot`: commit, base digest/commit, changed paths); база — архив засева, т.е. рабочее
дерево с dirty-правками, поэтому два узла с одинаковым HEAD и разным dirty diff — разные снимки.
`GET /api/runs/{id}/code` и `/code/diff?commit=` отдают их UI; панели в Inspector ещё нет.

## 2. Фактические гиперпараметры — P1

OPEN[experiment-runtime-parameters] proof:`absent:RuntimeSnapshotPanel@ui/src/Inspector.jsx`

**Есть.** Idea.params, применённые настройки из поддерживаемых carriers, сведения о расхождениях; в наших задачах сохраняется run_metadata.json. Единой полной таблицы runtime-параметров для env-рецептов пока нет.

**Нужно.** RuntimeSnapshotPanel: declared / applied / source, отдельно неизвестное значение и конфликт источников. Поддержать объявленные env/JSON/YAML carriers и runtime-артефакт задачи без вывода секретов. Самоотчёт кандидата не становится независимо подтверждённым фактом. Наличие поля в Idea не доказывает его применение.

**Приёмка.** lr, effective/global batch, micro batch, world size, max_steps, seed, precision, модель и выборка показаны из фактической конфигурации соответствующей попытки. Переопределение в коде и конфликт двух carriers видны; missing не превращается в ноль. Нельзя выводить «число примеров/с» из tree rows/s: единицы сохраняются.

**Данные есть (2026-10-14, doc 79 §6).** Событие `effective_config`: значения в канонических ключах
(lr, batch/micro batch, world size, max_steps, epochs, warmup, seed, scheduler) с источником
(env оценки / env-файл оверлея / лог стадии со строкой), сверка с объявленными params — `checked`,
`mismatches`, `unknown` (missing не ноль), `conflicts` по стадиям; есть в `GET /api/runs/{id}/code`
(`attempts[].effective_config`). Панели RuntimeSnapshotPanel ещё нет.

## 3. Предпросмотр файлов — P1

OPEN[experiment-artifact-previews] proof:`absent:ArtifactPreview@ui/src/RecordedSeedFiles.jsx`

**Есть.** Инвентарь, фильтр, ограниченный текстовый просмотр и просмотр recorded seed files. Бинарные файлы не становятся доступными для inline-просмотра только от наличия строки в инвентаре.

**Нужно.** Общий ArtifactPreview, подключённый и к recorded seed, и к артефактам попытки: PNG/изображения, ограниченные CSV-таблицы, структурированный JSON/YAML, PDF, метаданные файлов весов. Для неподдерживаемого файла — метаданные и скачивание. SVG/HTML из кандидата не исполняются в origin управляющего UI; для весов не выполнять pickle/код. Проверять run/generation/node/attempt/path и действующие права доступа.

**Приёмка.** На реальных графике, CSV, JSON, PDF и checkpoint-файле видно подходящее представление либо честный fallback. Большие/повреждённые файлы ограничены по времени и памяти, path traversal и активное содержимое не проходят. «Все файлы» означает доступный инвентарь и fallback, а не произвольное исполнение форматов.

## 4. Скорость и ресурсы в карточке эксперимента — P2

OPEN[experiment-resource-snapshot] proof:`absent:ResourceSnapshotPanel@ui/src/Inspector.jsx`

**Есть.** Времена стадий и наши training-resources JSON/CSV с wall time, GPU·ч и измерениями обучения. Пользователь явно попросил сохранять скорость для планирования ресурсов.

**Нужно.** ResourceSnapshotPanel с типом/числом GPU, world size, временем подготовки/обучения/оценки, steps/s, tree rows/s, GPU·ч, пиковыми ресурсами при наличии и ссылкой на исходный snapshot. Отдельно измеренные значения, вычисленные производные и прогноз. Привязка к attempt и checkpoint обязательна; повторные попытки и восстановление не смешиваются в одну скорость.

**Приёмка.** Для одного из завершённых 8-GPU запусков значения совпадают с сохранёнными JSON/CSV. Таблица позволяет оценить время похожего рецепта с явным предположением, не обещая линейного ускорения. Отсутствующие измерения не подменяются оценкой; units tree rows/s и expanded examples/s не смешиваются.

## 5. Последовательность и статус

Сначала снимок кода и applied-параметры, затем просмотр артефактов и единая поверхность ресурсов. Backend carriers/снимки и UI добавляются совместно с проверками привязки к попытке. Это отдельные изменения после уже установленных external-harness/Research исправлений doc 76; здесь ничего из нового трекера не объявлено реализованным.

Предложенные имена UI-компонентов обозначают точки реализации, а не уже существующие классы. Если реализация окажется в другом месте, перенести proof к реальному месту, которое решает вопрос. При частичной реализации proof отражает остаток; закрытие требует всей приёмки, удаления маркера и записи commit/проверок.
