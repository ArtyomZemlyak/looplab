**Граница причины.** Явный scope работает по объявленному фильтру. Пробел находится
в сценарии «тот же внешний агент создаёт новую кампанию»: одного создания run
недостаточно для его подключения к существующему hook, и текущая инструкция не
показывает этот следующий шаг. Доставка старых runs не доказывает связь с новым.

**Доработка.** В start/connection workflow проверять соответствие нового run scope
выбранного hook и сообщать `excluded_by_run_filter` с конкретным действием оператора.
Предлагать подключение только нужного run с сохранением остальных полей и полномочий;
не расширять фильтр до всех runs автоматически. Readback конфигурации, доставка,
прочтение агентом и GPU-запуск остаются разными наблюдениями.

**Приёмка.** При сохранённом узком фильтре новый run явно показан как исключённый.
После разрешённого подключения его уведомление доставляется выбранному агенту;
чужие runs не добавляются, команда и секреты не попадают в диагностический вывод,
повторное подключение не создаёт дополнительной кампании или GPU lease.
