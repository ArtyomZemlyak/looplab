## 5. Реестр находок

Формат: приоритет P0/P1/P2 — вклад в порог входа; размер S/M/L — локальная правка /
несколько согласованных поверхностей / изменение контракта. EB — entry barrier; нумерация
не пересекается с OB doc 71.

### A. Первые десять минут

#### EB-01 · P0 · S — README читается как каталог, а не как вход

**Наблюдение.** 3 110 слов. После 78 слов и одного блока установки идут: SVG архитектуры,
13 абзацев «Key features» (643 слова), «CLI quick start» с тремя командами, «Four ways to
configure a run» с четырьмя, YAML и абзац про `eval_env` (659 слов), затем «Run with a real
LLM», девять видов задач, 14 команд CLI, auth, crash & resume, Docker, «What a node may read».
**Предложение.** README ≤ 1 000 слов: что это (две фразы), один блок установки, пять строк пути
через Assistant, одна строка офлайн-демо, таблица ссылок. Всё остальное уже есть в guide — оставить
ссылки. **Приёмка.** README ≤ 1 000 слов; первая команда в первых 40 строках;
`tests/test_documentation_contracts.py` зелёный (команды остаются названы в guide).

#### EB-02 · P0 · S — Две истории установки

**Наблюдение.** README «Start with Assistant»: `pip install -e ".[ui]"`. README «Installation»:
четыре варианта (`.`, `[ui]`, `[otel]`, `[dev]`). Installation: «Source install for the web UI»
(clone/venv), потом отдельный «Install» с `pip install -e .` и таблицей зависимостей, потом шесть
extras, потом «Verify the install» через CLI-run. **Предложение.** Одна рекомендуемая команда
везде (`pip install -e ".[ui]"`); таблица extras один раз, в Installation; «Verify» = открыть
`looplab ui` и один офлайн run. **Приёмка.** Installation ≤ 500 слов; в README одна команда
установки.

#### EB-03 · P1 · S — Каждый пример несёт сноску про `backend=llm`

**Наблюдение.** `backend` по умолчанию `llm` (решение 2026-08-04), поэтому каждый пример без
модели требует `--backend toy`, а сноска об этом повторяется в README, Installation,
`CLAUDE.md` и дважды в configuration. Отказ без модели сам по себе хорош (§4.3).
**Предложение (пересмотрено, §12).** Не менять default и не добавлять команду: новая команда
увеличивает ту самую поверхность, которую сокращает EB-08. Единый файл запуска уже умеет нести
настройки, поэтому `examples/demo.yaml` (`task:` quadratic + `settings: {backend: toy}` + `out:`)
запускается без флагов: `looplab run examples/demo.yaml`. Страницы входа ссылаются на этот файл;
сноска про default остаётся в configuration. **Приёмка.** `looplab run examples/demo.yaml`
завершается < 10 с без сети; на страницах входа нет даты 2026-08-04.

#### EB-04 · P1 · S — Консоль теряет имя метрики

**Наблюдение (уточнено, §12).** `looplab run --no-genesis --kind dataset --data
examples/dataset_example/data.csv --backend toy` печатает `BEST node 2: metric=10 params={}`.
Toy-бэкенд для `dataset` пишет детерминированный шаблон, который считает строки файла, и сам
подписывает число: `"metric_name": "row_count (offline baseline)"`. Подпись лежит в событиях, но
итоговая строка CLI её не печатает, поэтому 10 читается как измеренное качество модели.
**Предложение.** Итоговая строка `run`/`resume`/`inspect` печатает имя метрики, когда оно
записано: `metric=10 (row_count (offline baseline))`. Отказ для `dataset` без модели не нужен:
шаблон честно назван, он служит проверкой конвейера. **Приёмка.** Тест: строка BEST содержит имя
метрики, если узел его записал.

#### EB-05 · снято — Предупреждение `CAP_DAC_OVERRIDE` в консоли

**Наблюдение (уточнено, §12; исправлено, §12.6).** WARNING на 500 символов печатается, когда
процесс держит `CAP_DAC_OVERRIDE` (root: этот контейнер, образ из `Dockerfile`, в нём нет `USER`) —
и на КАЖДОМ запуске под Windows, где у `runtime/read_fence.py::_dac_override` нет проверки
effective uid и правило режима файла не связывает никого. Второй проход написал «обычный
пользователь его не видит» — для Windows, которую Installation называет поддерживаемой, это
неверно: так печатала каждая задача Windows-CI. Это намеренное сообщение безопасности
(`runtime/read_fence.py::harden_guarantee`, вызов в `engine/resources.py`): read fence ставится и
на toy-задачу, потому что код кандидата может писать в журнал run. Последняя строка «That natural
completion is the one finish that names no reason» закреплена `tests/test_stop_account.py`.
**Решение (пересмотрено, §12.6).** Не понижать уровень и не переписывать: строка называет
настоящий остаток (нативный писатель, запущенный кодом кандидата, может перезаписать fence), и на
Windows он так же реален, как у root. Порог входа здесь — не сама строка, а то, что новичок не знает,
ожидаема ли она; поэтому Installation одной фразой называет её ожидаемой для Windows и root, а
`tests/test_entry_page_budgets.py` держит цитату равной началу настоящего сообщения. Перевод образа
на не-root пользователя ломает запись в bind-mount `./runs` на типичном хосте, поэтому не делается в
рамках порога входа.

#### EB-06 · P1 · S — Личные файлы запусков в корне репозитория

**Наблюдение (уточнено, §12).** §4.6: три `e5small_v1N.json` и `rubert_run_0804.json` — задачи

## 9. Отвергнутые альтернативы

- **Вернуть `backend=toy` по умолчанию.** Нет: решение 2026-08-04 защищает от «пустых» run с
  моделью, и отказ без модели уже называет исправление. Вместо этого `examples/demo.yaml` (EB-03).
- **Команда `looplab demo`.** Нет: файл запуска делает то же без новой команды (EB-03, §12).
- **Удалить справочные страницы или инструменты CLI.** Нет: `tests/test_documentation_contracts.py`
  требует, чтобы каждая команда была названа в guide, и это правильно. Группировать и
  переупорядочивать, не удалять (EB-08, EB-11).
- **Прятать оговорки в Report.** Нет: честность результата — свойство продукта. Менять порядок и
  слова, не состав (EB-21).
- **Отдельный «простой» UI.** Нет: он раздваивает маршруты и тесты. Режим Simple внутри того же
  workspace (EB-20) был более дешёвой заменой, но тоже снят (§12): run открывается Report, и его
  первую фразу исправил EB-21.
- **Переводить документацию.** Не в этом плане: сначала сократить, потом переводить.
